## Maintenance expectations

When source changes, update the owning guide and related links in the same PR. Preserve historical bodies and source tables; add dated corrections rather than silently revising evidence. Confirm npm script names in package.json, roles in server handlers/rules, locale coverage in the relevant registry, and asset deployment in post-build. Use relative repository links so the guides work in clones and on GitHub.

Documentation-only changes do not imply an application version bump, production deployment, or new permissions. See the authoritative policy for the checks required by the actual code/backend scope.
